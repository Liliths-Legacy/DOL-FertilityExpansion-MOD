## 2026-10-05：1.5.13 启动脚本拼接修复

用户报告启动时 `Error [tw-user-script-0]: {(intermediate value)...} is not a function`，随后侧栏 `edenSetup → edenSyncChildren` 报 `Cannot read properties of undefined (reading 'syncRegistry')`。

本地 ModLoader 2.101.1 的 `makeScriptNode` 将普通脚本合为一个用户脚本，仅在文件之间添加注释头与换行。生育拓展所有模块原本以 `(() => {...})()` 开头；前一个模组若以未加分号的对象赋值结束，JavaScript 会把下一模块的开头解析为调用该对象。使用打包清单的实际顺序，前置 `window.previousMod = {one: 1, two: 2, three: 3, four: 4}` 后可复现截图原文及 `EdenChildData === undefined`。这是后续孩子同步错误的上游原因；尚未确认用户组合中具体哪个模组提供了这个对象赋值。

修复：全部 21 个普通及早期模块改为以 `;(() => {...})()` 开头，保持原有初始化与存档处理逻辑。版本更新为 1.5.13。新增 `tests/eden-script-loading.test.js`：按 ModLoader 拼接方式和构建后的顺序执行，覆盖对象、函数调用、数组和字符串结尾的前置脚本，并逐个验证模块能作为第一段脚本加载、验证编号 0 的登记及已保存简介保留。Python 打包测试从最终 ZIP 解出脚本后运行同一回归测试，防止只修源文件却漏打包。

验证：173 项 JavaScript 测试及 11 项 Python 测试通过，无失败或跳过；最终 ZIP 脚本拼接回归通过。在本机 0.5.12.13 / ModLoader 2.101.1 游戏页面实际加载修复包，完成新游戏启动并进入含侧栏的初始场景，未出现弹窗报错或 `.error` 元素。本次未复现用户手机上的完整第三方模组组合，也未重新进行下方历史记录中的三份旧档浏览器检查；旧档与孕期迁移自动测试通过。
